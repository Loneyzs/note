# FDSim 场景自动搭建

在当前已登录的 FDSim 浏览器工程内执行场景搭建。优先复用已验证流程；新操作必须留下可复查证据，再写入参考资料。

## 开始前

1. 读取 [references/verified-workflows.md](references/verified-workflows.md)。
2. 接管用户当前已登录并已打开工程的浏览器标签页。优先使用 Playwright MCP 或应用内浏览器的语义化定位能力。
3. 记录 FDSim 版本、项目名、场景名和当前是否有未保存修改。
4. 把用户目标拆成最小可验证闭环；若成功标准不明确，先询问，不直接搭建。

## 执行纪律

- 优先按角色、文本、标签和组件树定位；仅在没有可访问语义时使用坐标点击。
- 每次只做一个可观察的变更，随后检查组件树、属性面板或运行状态。
- 给新对象使用稳定且可搜索的名称，如 `Robot_UR5`、`PICK_P1`、`SampleBox_01`。
- 未经用户明确授权，不覆盖原组件、不删除已有对象、不保存探索性改动。
- 在点击保存前汇总待保存变更；只有目标闭环验证通过或用户明确要求时才保存。
- 浏览器工具不可用、登录失效或目标控件不可见时，停止并报告，不假装完成。

## 搭建工作流

1. **勘察**：读取当前布局、组件库、行为树、程序、通信配置和资源入口。
2. **规划**：优先采用平台内置控制器和行为，避免用外部程序重复实现运动学或物流机制。
3. **搭建**：按“组件 → 行为/程序 → 信号 → 通信 → 运行”的顺序创建。
4. **验证**：分别验证静态结构、单步动作、信号握手和完整循环。
5. **交付**：报告已创建对象、变量映射、验证结果、未验证项和是否保存。

## 机器人与 OPC UA

- 固定运动优先采用“外部 OPC UA 触发 + FDSim 内部点位程序”，不要持续下发六轴关节值。
- 使用 `Start` 触发动作，用 `Done` 回写完成状态；多任务时再增加 `RecipeId` 或 `TargetId`。
- 点位、速度、轨迹和逆运动学留给 FDSim 机器人控制器。
- 没有真实 OPC UA 端点时，只能标记为“配置路径已验证”，不能标记为“端到端已验证”。

## 视觉样本与物流

- 先用 2 个样本验证贴图、生成、输送和到位握手，再扩展到完整样本集。
- 样本顺序应可复现：外部程序用固定种子生成 `SampleIndex`，FDSim 按编号生成组件。
- 使用 `Arrived` 和 `VisionDone` 建立到位与放行握手，记录样本编号、随机种子和结果。
- 未确认平台自带随机选择能力前，不把“随机”界面选项写成确定步骤。

## 维护已验证知识

每次获得新的实际操作结果后，更新 `references/verified-workflows.md`：

1. 写明测试日期、FDSim 版本和入口路径。
2. 用以下等级标记证据：`界面已见`、`文档确认`、`实操通过`、`端到端通过`、`待验证`。
3. 只把可重复成功的操作写成命令式步骤；失败尝试写入“已知限制”。
4. 版本变化导致入口或字段改变时，保留版本条件，不直接覆盖旧结论。
5. 更新后运行 Skill 校验器，确保元数据和文件结构有效。
