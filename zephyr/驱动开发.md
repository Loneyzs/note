# 完整驱动开发

### 项目结构

```
my_project/
├── dts/
│   └── bindings/            # 硬件描述规则（The Law）
│       └── <vendor>,<driver>.yaml
├── include/
│   └── zephyr/
│       └── drivers/         # 公开 API 定义（The Manual）
│           └── <subsystem>.h 
├── drivers/                 # 驱动核心实现（The Factory）
│   ├── CMakeLists.txt       # 驱动子目录索引
│   ├── Kconfig              # 驱动配置入口
│   └── <subsystem>/
│       ├── CMakeLists.txt   # 编译逻辑
│       ├── Kconfig          # 具体驱动的配置开关
│       ├── <driver>_priv.h  # 内部私有结构与寄存器定义
│       └── <driver>.c       # 核心实现（DEVICE_DT_DEFINE 所在地）
├── boards/                  # 板级适配
│   └── <board_name>.overlay # 定义具体的硬件节点（DTS 实例）
├── app/                     # 测试应用（The User）
│   ├── src/
│   │   └── main.c           # 调用 DEVICE_DT_GET
│   ├── prj.conf             # 开启 CONFIG_<DRIVER>
│   └── CMakeLists.txt
└── CMakeLists.txt           # 顶层构建文件
```

### 硬件开发链路

1. 硬件描述层 dts  (.dts / .overlay)：硬件实例描述入口，负责描述 硬件实例的具体信息。
   * 兼容性标识 (`compatible`)：唯一字符串，将硬件节点和驱动程序、绑定文件结合
   * 硬件资源分配：配置片内外设引脚、硬件参数 (波特率等) 等信息
2. 约束定义层 Binding  (.yaml)：规定compatible节点下的属性
   * 存储驱动硬件参数的定义：eg. 串口驱动在绑定文件里有波特率的定义
3. 构建系统转换：将硬件信息结合，生成C语言宏定义

### 软硬件结合

1. 创建硬件实例：`drivers/xx,c` 源码中通过 `DEVICE_DT_DEFINE` 创建硬件实例结构体
   * 静态配置区：寄存器物理基地址等硬件参数，不可更改
   * 操作接口区：具体驱动函数指针
   * 运行状态与数据区：实现驱动函数的私有信号量、互斥锁、缓冲区等设置
   * 元数据区：命名等系统管理参数
2. 应用：应用层通过 `DEVICE_DT_GET` 调用实例中驱动方法
   * 直接指向 `drivers/xx,c` 完善好的结构体实例

### 软件部分：

在 `drivers/xx,c` 中完善创建实例内部方法
